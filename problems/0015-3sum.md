## 1. Pattern Recognition & Triggers

- **Clues in prompt:** *"return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, `j != k`, and `nums[i] + nums[j] + nums[k] == 0`"*, *"the solution set must not contain duplicate triplets"*, `nums.length <= 3000`.
- **Core intuition:**
  - Algebraic transformation: 
    $$nums[i] + nums[j] + nums[k] = 0 \iff nums[j] + nums[k] = -nums[i]$$
  - Once the array is **sorted**, fixing element $nums[i]$ reduces the problem for the remaining suffix ($i + 1 \dots n - 1$) directly to **Two Sum II** (LeetCode 167) where the target is $-nums[i]$.
  - Sorting gives two decisive advantages:
    1. **Monotonicity for Two Pointers:** Enables bidirectional inward convergence in $O(N)$ time per fixed $i$.
    2. **Duplicate Grouping:** Identical values become strictly adjacent, allowing effortless $O(1)$ duplicate skipping without needing expensive hash sets or string serialization.

---

## 2. Approach & Trade-offs

1. **Approach 1 — Brute Force with Set ($O(N^3)$ Time, $O(N)$ Space):**
   - Three nested loops checking every combination of $(i, j, k)$. Triplet components are sorted and inserted into an `std::set<vector<int>>` to remove duplicates.
   - *Verdict:* With $N = 3000$, $N^3 \approx 2.7 \times 10^{10}$ operations $\rightarrow$ massive Time Limit Exceeded (TLE).

2. **Approach 2 — Hash Map / Hash Set ($O(N^2)$ Time, $O(N)$ Space):**
   - Fix $i$, then run standard Two Sum with an `unordered_set` on the remainder.
   - *Verdict:* Satisfies $O(N^2)$ time, but handling duplicate triplets without pre-sorting requires storing vectors in a hash set with custom hash functions, adding heavy memory overhead and high constant factor penalties.

3. **Approach 3 — Sort + Two Pointers (Optimal & Implemented):**
   - Sort `nums` in non-decreasing order ($O(N \log N)$).
   - Iterate $i$ from $0$ to $n - 3$:
     - **Skip duplicate first values:** If $i > 0$ and $nums[i] == nums[i - 1]$, skip via `continue`.
     - **Early termination optimization:** If $nums[i] > 0$, break immediately. Because the array is sorted, all subsequent numbers are also $\ge nums[i] > 0$; their sum cannot possibly equal $0$.
     - Initialize two pointers: `left = i + 1` and `right = n - 1`.
     - While `left < right`:
       - `sum = nums[i] + nums[left] + nums[right]`.
       - If `sum == 0`: Record `{nums[i], nums[left], nums[right]}` into `result`. Advance `++left` and `--right`. Then skip all adjacent duplicate values for `left` and `right`.
       - If `sum < 0`: Increment `++left` (need a larger sum).
       - If `sum > 0`: Decrement `--right` (need a smaller sum).
   - *Verdict:* Strictly optimal $O(N^2)$ time and $O(1)$ auxiliary space. Zero hash table overhead, cache-locality friendly.

---

## 3. Complexity Analysis

- **Time Complexity:** $O(N^2)$
  - Sorting `nums` takes $O(N \log N)$.
  - The outer loop runs $N - 2$ times. For each iteration, the two pointers `left` and `right` traverse inward, visiting each remaining element at most once in $O(N)$ time.
  - Overall time: $O(N \log N) + O(N^2) = O(N^2)$. With $N \le 3000$, $N^2 \approx 9 \times 10^6$ operations, executing comfortably within ~30ms.
- **Space Complexity:** $O(1)$ auxiliary space
  - Excluding the `result` vector (mandated for return) and compiler-dependent recursive stack frames for `std::sort` ($O(\log N)$), no auxiliary containers (sets, maps) are used.

## 4. Edge Cases & Gotchas

- [x] **Duplicate triplets prevention (The Crucial Gotcha):**
  - **Duplicate `i`:** Must check `if (i > 0 && nums[i] == nums[i - 1]) continue;`. Do **not** check `nums[i] == nums[i + 1]`, because that would prematurely skip valid combinations that utilize identical values (e.g. `[-1, -1, 2]`).
  - **Duplicate `left` & `right`:** Must first advance `++left; --right;` upon finding a match, and *then* skip while `nums[left] == nums[left - 1]` and `nums[right] == nums[right + 1]`.
- [x] **Early stopping optimization (`nums[i] > 0`):**
  - In a sorted array, if the smallest value of the triplet is already $> 0$, the sum of three positive numbers can never equal $0$. Breaking early saves unnecessary scans.
- [x] **All zeroes (e.g. `nums = [0, 0, 0, 0]`):** Correctly yields a single unique triplet `[[0, 0, 0]]` without duplicates.
- [x] **Small inputs ($N < 3$):** Outer loop bounds `i < n - 2` with `int n = nums.size()` safely prevents executing the loop, immediately returning an empty `result`.

## 5. Clean Code (Optimal Solution: Sort + Two Pointers)

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        sort(nums.begin(), nums.end());
        int n = nums.size();

        for (int i = 0; i < n - 2; ++i) {
            // Skip duplicate first values
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            // Since the array is sorted, no later triplet can sum to 0
            if (nums[i] > 0) {
                break;
            }

            int left = i + 1;
            int right = n - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {
                    result.push_back({nums[i], nums[left], nums[right]});
                    ++left;
                    --right;

                    // Skip duplicate second and third values
                    while (left < right && nums[left] == nums[left - 1]) {
                        ++left;
                    }
                    while (left < right && nums[right] == nums[right + 1]) {
                        --right;
                    }
                } else if (sum < 0) {
                    ++left;
                } else {
                    --right;
                }
            }
        }

        return result;
    }
};
```

## 6. Review & Takeaways

### Step-by-Step Dry Run

Given input: `nums = [-1, 0, 1, 2, -1, -4]`

After sorting: `nums = [-4, -1, -1, 0, 1, 2]`

```text
i = 0, nums[0] = -4:
  left = 1 (-1), right = 5 (2)
  sum = -4 + (-1) + 2 = -3 < 0 -> ++left
  sum = -4 + (-1) + 2 = -3 < 0 -> ++left
  sum = -4 + 0 + 2 = -2 < 0    -> ++left
  sum = -4 + 1 + 2 = -1 < 0    -> ++left (left meets right, exit inner loop)

i = 1, nums[1] = -1:
  left = 2 (-1), right = 5 (2)
  sum = -1 + (-1) + 2 = 0 == 0 -> Found! Record [-1, -1, 2]
  Advance: ++left (now at 0), --right (now at 1)
  Skip duplicates: None
  Next: sum = -1 + 0 + 1 = 0 == 0 -> Found! Record [-1, 0, 1]
  Advance: ++left (now at 1), --right (now at 0) (left > right, exit inner loop)

i = 2, nums[2] = -1:
  nums[2] == nums[1] (-1 == -1) -> Duplicate first element!
  continue (skips re-evaluating -1, preventing duplicate triplets)

i = 3, nums[3] = 0:
  left = 4 (1), right = 5 (2)
  sum = 0 + 1 + 2 = 3 > 0 -> --right (left meets right, exit inner loop)

Loop terminates. Final Result: [[-1, -1, 2], [-1, 0, 1]]
```

### The Two Pointers Evolution Ladder

```text
Two Sum (Unsorted)
    └─ Hash Map: O(N) Time, O(N) Space

Two Sum II (Sorted)
    └─ Two Pointers: O(N) Time, O(1) Space

3Sum (Unsorted, No Duplicates)
    └─ Sort + Fix i + Two Sum II + Skip Duplicates: O(N²) Time, O(1) Space
```

### The Architectural Pattern

```text
3Sum: nums[i] + nums[left] + nums[right] == 0
                 ↓
             Sort Array
                 ↓
        Iterate i from 0 to n - 3
        ├─ if (i > 0 && nums[i] == nums[i - 1]) continue; (Tránh duplicate i)
        ├─ if (nums[i] > 0) break; (Dừng sớm: mọi số sau đều > 0)
        └─ Two Pointers (left = i + 1, right = n - 1):
             ├─ sum < 0  → ++left
             ├─ sum > 0  → --right
             └─ sum == 0 → Thêm triplet vào result
                           ++left; --right;
                           Bỏ qua duplicate left (nums[left] == nums[left - 1])
                           Bỏ qua duplicate right (nums[right] == nums[right + 1])
```
